# 已审核方案 Word / PDF 导出设计

日期：2026-10-14。状态：书面设计与实施计划已获用户确认；Native 实施及验收完成，改动保留在现有工作区，未提交。

## 1. 用户目标与范围

用户希望技术审核通过后，从方案详情页下载可编辑的 Word 和固定版式的 PDF，保留方案正文、版本、审核信息和来源引用。导出读取已保存的获批版本，不重新生成、不调用 LLM，也不改变审批、客户需求或历史方案。

本轮选择后台双格式生成。浏览器打印方案部署较轻量，但文件版式依赖浏览器；后台生成需要文档依赖和中文字体资产，便于统一内容投影及下载时校验。

保留当前脏工作区与用户未提交改动，不自动提交、切换分支或清理文件。不修改 PostgreSQL 实例、配置、角色、模板或扩展。

不包含草稿导出、过期版本正式导出、批量导出、匿名分享、邮件发送、电子签章、报价/合同生成、在线编辑或文件重新导入。

## 2. 已核实的项目基线

- 当前 API 没有导出路由；详情页只有查看、刷新及审核动作。
- `visible_solution_drafts_for()` 定义业务角色/对象边界，额外允许独立售前审核人查看其被指派的确切版本；该权限不授予整个商机可见性。
- `deserialize_solution_payload()` 支持严格 V1/V2 读取；导出不能跳过现有 payload 校验。
- `evaluate_solution_draft_stale_reasons()` 是只读状态检查，覆盖新分析、企业事实审批/状态及来源索引和内容一致性。导出不调用会保存 stale 元数据的刷新函数。
- 该 stale 检查目前不独立比较尚未重新分析的原始需求变化。导出新增本地的需求原文漂移拒绝，不修改全局审核或 stale 规则。
- 方案 151 在本次只读核对时为 V2 / 方案版本 2 / APPROVED，分析快照 298，无派生 stale 原因，存在一条批准记录；可用作实施完成后的读取验收样例，不修改其内容或审核。
- 项目运行环境已有 pypdf，尚未安装 python-docx / ReportLab。本文不安装依赖或生成样例文件。
- GitNexus 已绑定本项目，但 2026-10-03 索引因 storage 43 / runtime 42 不兼容而无法查询；图谱覆盖为 UNKNOWN，不重建索引。当前源码和测试是设计依据。

## 3. 接口与权限

新增只读下载接口：

`GET /api/solution-drafts/{solution_id}/export/?file_type=docx|pdf`

使用 `file_type`，不复用 DRF 内容协商使用的 `format` 参数。接口不接受客户端正文、引用、审核状态、模板、字体路径或“强制导出”选项。

所有条件必须同时成立：

1. 用户已认证、仍活跃，业务 role 为 Sales / Presales / Admin。技术 staff/superuser 标记不改变业务权限。
2. 从现有 `visible_solution_drafts_for()` 取到这个确切版本；不可见版本返回 404，不泄漏其审核状态。
3. 当前方案投影为 APPROVED，且存在该版本的真实已决定 APPROVED 审核记录；不能仅凭投影字段或 workflow 状态通过。
4. 不存在已存或实时计算的 stale；当前商机原始需求与分析快照的 `source_raw_requirement` 按现有 strip 口径一致。需求已变化时拒绝作为当前方案导出，不覆盖历史快照。
5. persisted payload 通过既有版本校验，企业引用与 durable provenance 的对应关系完整，并通过当前审批、索引和内容复核。不能因 provenance 行缺失而把“无可核对条目”当作有效。

“有效版本”遵守以上条件，不另加“必须是最大方案版本号”的新规则。一个较早但仍有效的获批版本可按用户明确选择导出；有新分析时仍按既有规则失效。

## 4. 内容投影与隐私边界

增加独立导出服务，不进入 LangGraph 生成或审核节点。经过权限和有效性检查后，将严格反序列化的 V1/V2 数据转换为同一种只读文档投影，两个 renderer 共用。

不读取页面 DOM，不依赖用户展开引用弹窗，不拿客户端缓存代替数据库记录，不读取当前客户/商机其它字段来补写获批方案。独立审核人下载的内容不会超出其已有版本级可见数据。

### 公共页首

保存的方案标题、方案 ID、方案版本、schema 版本、分析快照 ID、创建时间、创建人 ID、批准审核记录 ID、审核人 ID、通过时间、导出时间。人员使用已有版本 API 的 ID 口径，不额外查询联系方式。

默认只包含批准记录的必要元数据，不包含完整失败/退回历史、内部审核备注、客户原始需求全文、异常诊断或供应商密钥。

### V2 正文

按当前结构顺序展示：执行摘要、客户事实/未确认事项、总体方案及能力建议、系统架构、部署与集成、实施计划、技术风险、验收标准、里程碑、假设、待确认问题、范围外事项。

解析 claim ID 为保存的原文，保留客户事实、企业事实、建议、假设、未确认类别，不能把建议改成能力承诺。保留组件职责/理由/接口、依赖及 request/data flow 的端点和方向，阶段目标/任务/交付物/责任角色/依赖/时间/验收关系，风险各字段和验收/时间/范围分类。

组件和阶段关系先用确定性的文字或表格呈现，不重新推导架构图。没有某个可选内容时不编造填充；有引用但缺被引用对象时失败，不静默省略。

### V1 正文

通过独立适配器展示执行摘要、原有五个方案章节及假设。使用 statement path 对接既有 provenance；不迁移或升级历史 schema。

### 来源附录

正文保留准确引用编号和 claim ID / statement path，附录提供对应的来源编号、文档 ID 与可见标题，保持引用对应关系。V1 不能得到安全可见标题时使用文档 ID，不额外扩展知识库权限。

默认不附完整知识库原文或 source excerpt，不提供匿名源文件下载链接，不请求外部 URL。原始来源状态复核仍照常执行，省略 excerpt 不是跳过 grounding。

固定声明：本文件为导出时有效的内部技术审核版本，可用于技术沟通；不构成报价、合同、客户验收、性能或 SLA 承诺。导出后的编辑内容不自动继承系统审核。

## 5. 生成与返回时复核

1. 取当前 actor 与可见方案，执行第 3 节全部 gate。
2. 建立不可变导出投影及一致性指纹，包含本次使用的方案版本/payload、分析身份、批准记录和引用/provenance 元数据；不把正文写入日志。
3. 在内存生成文件，不在渲染期间长期占用数据库行锁，也不存放公开文件或创建业务数据行。
4. 渲染结束，在短复核边界重新读取 actor 活跃状态/role、版本可见性、审核、原需求、payload 和当前来源；重新执行同一 gate，并确认投影指纹未变。需要行锁时使用现有模型正常事务访问，不变更 PostgreSQL 实例配置。
5. 只有最终复核通过才构造一次性二进制响应；不使用预先发出的流式响应，不先返回部分文件再发现失败。

最终复核时点之后发生的权限或来源变化不能追回已下载文件；文档标明导出时间，不承诺文件永久有效。变更或无法复核时失败关闭，不调用模型、不自动重试或回退到旧文件。

## 6. 文件格式、安全与运行依赖

- Word 使用 python-docx 生成真正的无宏 `.docx`，PDF 使用 ReportLab 直接生成，不把 Word 伪装成 PDF，也不在生产运行依赖 Office / LibreOffice 转换。
- A4 纵向，清晰的章节层级、适度页边距、正文和列表自动换行、表格跨页、页眉版本标识与页码。禁止裁剪正文、来源或未确认事项以满足页数。
- PDF 内嵌可分发的 Noto Sans SC 常规字重 TrueType 字体，字体资产和 OFL 许可纳入应用；若上游资产需要静态化，作为实施期间一次性的资产准备，不在导出请求内下载或转换。Word 设置中文字体并允许客户端替代字体，两个格式页数不要求完全相同。
- 没有可用 PDF 字体/渲染依赖时返回明确服务不可用错误，不能生成缺字或空白文件后声称成功。依赖的具体相容版本、字体来源修订和哈希在实施计划中锁定。
- 一切方案文本作为数据：DOCX 使用普通文本写入；ReportLab 段落 markup 特殊字符转义。不执行 HTML、Markdown 图片、宏或外部链接，不按正文下载文件。
- 文件只在内存持有；默认最大 10 MiB，超限整体拒绝而非截断。不新增对象存储、公开分享、数据库导出模型或迁移。
- 文件名使用固定前缀及数字 ID/版本：`SalesMind-solution-151-v2.docx` / `.pdf`，不把用户标题直接当路径或 HTTP header。
- 响应包含正确 MIME、`Content-Disposition: attachment`、`Cache-Control: private, no-store`、`X-Content-Type-Options: nosniff`；业务错误仍是安全 JSON，不把错误页保存为成功文档。
- 成功/拒绝日志只记用户 ID、方案 ID/版本、格式、受控原因类别和导出时间；不记完整正文、原需求、source excerpt、token 或异常 cause。

技术依据：[python-docx 官方文档](https://python-docx.readthedocs.io/en/latest/)、[ReportLab Paragraph 文档](https://docs.reportlab.com/reportlab/userguide/ch6_paragraphs/)、[Noto Sans SC OFL 文件](https://github.com/google/fonts/blob/main/ofl/notosanssc/OFL.txt)。

## 7. 前端行为与错误合同

方案详情页“刷新”附近增加“导出 Word”“导出 PDF”，仅在页面显示获批且未过期时可用。前端状态仅用于体验，后端决定是否放行；所有可见版本用户均使用同一下载接口。

请求复用当前 JWT / session 变化防护；二进制下载保留认证，不把 token 放入 URL。下载期间显示忙碌状态并阻止重复点击。Blob URL 在完成后释放。

下载响应的格式和 MIME 必须符合所选类型。错误 Blob 读取安全 JSON，并交给统一受控错误映射；不直接显示后端原文或浏览器对象字符串。409 显示状态/依据已变化、需核对的提示，可刷新版本，但不能自动生成或循环导出。路由或账号变化后不把旧请求文件交给新页面/账号。

| 情况 | HTTP / 安全类别 |
| --- | --- |
| 未认证或无业务角色 | 既有 401 / 403 合同 |
| 版本不可见或不存在 | 404，不区分存在性 |
| 非法 file_type | 400 `solution_export_unsupported_format` |
| 未获批或缺有效批准记录 | 409 `solution_export_not_approved` |
| 已过期、事实或索引/来源失效 | 409 `solution_export_stale` |
| 原始需求改变 | 409 `solution_export_requirement_changed` |
| 生成期间投影或权限上下文改变 | 409 `solution_export_changed`；已失去可见性时按 403/404 |
| payload / 引用对应不完整 | 422 `solution_export_invalid_payload` |
| 导出文件超限 | 422 `solution_export_too_large` |
| 依赖/字体不可用或渲染失败 | 503 `solution_export_unavailable` |

不把任何下载错误描述为“请补客户条件”，也不把技术审核等同于客户正式验收。

## 8. 验证与交付标准

先写失败测试，再实施，完成后进行独立检查和完整项目回归：

- 权限：匿名、错误业务 role、staff-only、他人商机、独立版本审核人以及账号/role/归属变更。
- 状态：draft / pending / returned / approved，伪造 approved 投影但无批准记录，新分析、原文变化、事实撤销、索引变化、chunk 内容变化、缺 provenance。
- 返回时：在真实 renderer 边界注入上述变化，必须无成功二进制响应；不能只测启动时 gate。
- 内容：真实严格 V1/V2 payload，完整章节及关系、引用编号、分类、条件边界、批准元数据、固定声明一致；不向数据库写新方案或审批，不调用 LLM / embedding。
- 文件：中文、英文、特殊字符、长文本、跨页列表/表格、无来源片段泄漏、正确文件结构/MIME/名称、字体缺失及超限。DOCX/PDF 抽取文字校验之外，渲染为页面图像逐页核对，不能仅凭 ZIP/PDF header 判断交付质量。
- 前端：按钮状态、两种格式成功下载、错误 Blob、重复点击、409、认证刷新/退出、路由变化、对象 URL 清理。
- 运行验收：重启加载后，经真实认证从方案 151 下载两种文件，核对其获批版本和来源；不生成新方案，不修改现有审批，不依赖模型额度。若样例此时已失效，则报告阻塞而不是临时重新批准或修改数据。
