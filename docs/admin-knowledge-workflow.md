# Admin 知识文档与企业事实操作

本入口属于 Django `/admin/`，不是 Vue 销售工作台。它复用现有索引、事实抽取和人工审批，
不依赖 `seed_demo`。需要知识域 `0004_grounding_fact_extraction_attempt` 表结构；
开发阶段不自动应用业务库迁移、不重启项目，实际启用须由用户确认后部署。
本机已于2026-10-16经用户确认应用该迁移并启动后端；其他环境仍需单独部署。

## 账号条件

必须同时满足：账号有效、`is_staff=True`、业务角色为 `admin`。
仅有技术 superuser、仅有业务 admin，或 Sales/Presales 加后台标记都不能代替这些条件。
本功能不自动给账号提升权限。审批沿用同一双门权限。

## 正常操作

1. 登录 `/admin/`，打开“企业知识库 → 知识库文档”，点击“上传知识文档”。
2. 填写标题、资料类型并选择文件，确认上传和索引。支持 UTF-8 TXT、Markdown、
   可提取文字的 PDF；沿用文件大小、PDF 页数、编码和解析限制，不支持 Word 原生导入或 OCR。
   此步骤可能调用配置的 embedding 服务；索引就绪不等于已经抽取或批准事实。
3. 在文档只读详情点击“确认抽取待审事实”，核对当前文档/索引版本和费用说明，再提交。
   此步骤可能调用配置的 LLM；它只能生成待审核候选，不能替人批准。
4. 打开“查看该文档的事实与审核记录”，逐条核对事实状态、陈述、来源摘录和来源版本，
   选择“批准选中的 Grounding 事实”或“拒绝选中的 Grounding 事实”。不要只看模型生成的陈述。
5. 方案生成仍使用已保存需求快照，并经过原事实准入、来源、引用和技术审核。
   批准一条事实不保证它适用于每个方案；过期或来源不匹配的事实仍不能引用。

没有提供通用事实新增、编辑、删除或覆盖旧文档文件的功能。资料修订请上传新文档；
现有文档的“重建索引”用于重新解析其存储的源文件，并不提供后台直接替换文件的入口。

## 看懂状态

| 状态 | 含义与下一步 |
| --- | --- |
| 尚未完成索引 / 索引失败 | 先处理资料或配置；初次失败保留安全错误记录，检查后重新上传 |
| 索引就绪，尚未抽取 | 可用于原知识检索，但还没有通过本入口提出企业事实 |
| 抽取中 | 重复提交不会再次调用模型；刷新详情核对，不连续点击 |
| 抽取成功，无候选事实 | 本次确实完成但未提出候选，不会因空结果自动重试，也不代表已确认某种企业能力 |
| 存在待审核事实 | 需要人工核对后批准或拒绝，不自动授予方案准入 |
| 抽取失败 / 已取消 | 旧记录保留；重新打开抽取确认页，确认后才创建下一次尝试 |
| 已有历史事实 | 当前版本已有旧入口生成的事实；不伪造执行历史、不重复抽取，先查看其审核记录 |

同一文档同一索引版本只允许一个进行中或成功的执行记录；成功结果包括零候选。
错误说明使用固定白名单，不在页面显示模型原文、密钥、异常堆栈或内部存储路径。

## 中断、取消与重试

执行中断后数据库可能仍显示“抽取中”，这不是成功证明，也不会按时间自动重新付费执行。
在详情下方执行历史中核对对应记录，进入“核对并取消”，阅读说明并勾选确认。

取消会撤销旧执行保存结果的资格；即使其后返回，也不能写入候选。
但取消不保证终止远端模型请求或撤销已经发生的费用。需要重试时必须另开抽取确认页，
旧的失败确认页不能被反复重放来连续创建新尝试。

索引版本变化会使旧确认页失效；不要修改隐藏字段或强制提交。刷新文档核对后再操作。
重建索引成功后，旧事实过期，新版本的候选重新处于待审核状态，不能继承原批准信息。
重建一旦开始，正在执行的旧抽取即失去保存资格；即使重建失败并保留原索引，
旧抽取也不会恢复。需要再次抽取时，重新打开确认页明确重试，原执行记录继续保留。
历史事实和执行记录不会为了“恢复可用”而被删除或改成成功。

## 验证与限制

自动化通过临时数据库、临时媒体目录和 fake/deterministic providers 验证后台请求边界、
人工审批衔接、重复请求、并发锁、取消后的迟到结果以及索引切换。
这些离线验证不等于真实 LLM 抽取质量、生产容量或任意真实资料的成功率证明。

本功能保持同步请求，没有新增任务队列、自动格式重试、自动审批或生产限流体系。
执行记录防止本入口的重复执行，不对任意内部 shell 或 benchmark 调用作全局付费防重承诺。
